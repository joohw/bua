让任意 Agent 操作用户真实浏览器

BUA（Browser Use Agent）是面向 AI Agent 的浏览器使用层。扩展直接使用你已登录的标签页、Cookie 和会话，Agent 通过本地桥读取页面、截图、点击、输入、滚动与导航。无需重启浏览器，也无需开放 CDP 调试端口。

安装浏览器扩展 接入 DeepSeek Harness

为什么选择 BUA

  • 真实浏览器，真实登录态

    沿用用户正在使用的浏览器配置、Cookie 与登录状态，不必把账号密码交给新的自动化实例。

  • 不改调试配置

    通过 MV3 扩展的 chrome.debugger 操作页面，不需要重启浏览器，也不需要开放 CDP 端口。

  • 一套能力，多种接入

    DeepSeek Harness 原生插件、MCP stdio 与 @bua/sdk 共用同一套协议和工具。

  • 本地优先

    本地桥只监听 127.0.0.1:17432，操作记录可追溯，数据不离开本机。

支持的接入方式

接入方式适用客户端说明
DeepSeek Harness 原生插件 DSH 安装 dsh-plugin-bua，插件自动启动或复用本地桥，工具以 bua_* 出现。
MCP stdio OpenClaw、Hermes Agent 等 手动启动本地桥，为客户端配置 stdio 入口。
@bua/sdk 自研 Agent 在工作区内连接本地桥，按标签页调用读取、截图与操作能力。

三步开始

  1. 安装 BUA 浏览器扩展，并在引导页阅读风险告知后主动启用。
  2. 接入 Agent：DSH 用户安装 dsh-plugin-bua；其他客户端按 接入指南配置 MCP 或 SDK。
  3. 让 Agent 先调用 bua_browser_info 确认扩展后端，再用 bua_tabs_list 列出标签并开始只读验证。

安全模型

BUA 不做调用方身份认证。任何能访问本机回环地址的进程都可能通过本地桥操作浏览器，包括已登录页面。首次启用前请阅读并同意扩展引导页的披露；不要把本地桥暴露到公网。浏览器企业策略、受限页面或其他调试器占用可能使部分操作不可用。

常见问题

BUA 需要重启浏览器或开放 CDP 调试端口吗？

不需要。BUA 通过 Chrome MV3 扩展使用 chrome.debugger 操作页面，Agent 通过本机回环地址上的本地桥调用扩展，不要求重启浏览器，也不要求开放远程调试端口。

BUA 支持哪些 Agent 或框架？

DeepSeek Harness 使用原生插件 dsh-plugin-bua，由插件自动管理本地桥；OpenClaw、Hermes Agent 及其他客户端通过 stdio MCP 接入；也可以使用 @bua/sdk 自行集成。

BUA 和 Playwright、Puppeteer 有什么区别？

Playwright 和 Puppeteer 通常启动独立的浏览器实例；BUA 直接使用你现有的标签页、Cookie 和登录态，适合需要沿用真实会话的 Agent 任务，两者可以配合使用。

BUA 会收集或上传浏览数据吗？

不会。扩展不收集、不存储、不上传浏览数据，本地桥只监听 127.0.0.1，详情见隐私政策。

如何验证浏览器链路已经连通？

让 Agent 调用 bua_browser_info，成功返回扩展后端即表示链路可用；随后调用 bua_tabs_list 只读列出标签，再用 bua_tab_info 核对标题和网址。
