BROWSER USE AGENT

连接你的真实浏览器

让任意 Agent 操作你的真实浏览器

它做什么

  • 读取你当前标签页的内容（DOM、无障碍树）
  • 截图
  • 代你点击、输入、滚动、导航
  • 在你已有的登录态下操作 —— 不需要重新登录

⚠ 风险告知 —— 请务必读完

  • BUA 不校验调用方身份。任何能访问本机 127.0.0.1 的程序都可以连接 BUA 桥，并操作你的浏览器。
  • 它能读到你的全部标签页内容，包括已登录的邮箱、网盘、后台管理系统。
  • 它发起的操作无法撤销 —— 提交表单、支付、删除、发送消息一旦发生就收不回来。
  • 本机上的恶意软件本来就拥有你的用户权限；BUA 没有给它新的能力上限，但降低了门槛 —— 从「解析 Chrome 配置格式」降到「发一条 WebSocket 消息」。
这是刻意的设计取舍：为了「让任意 Agent 都能用浏览器」，我们没有引入配对凭据。 如果你需要隔离，请勿启用，或只在专用机器/专用 profile 上使用。

Chrome 的调试横幅

  • Agent 操作期间，Chrome 顶部会常驻一条「正在调试此浏览器」横幅。这是 Chrome 的行为，无法隐藏。
  • 关闭那条横幅会立即终止本次操作会话。
  • BUA 会另外给页面加一圈蓝色边缘泛光表示「正在被操作」；降级或出错时变成琥珀色。

连接方式

扩展通过固定的本地端口连接桥，无需也无法配置。 在终端启动桥即可： 

bua-server
连接地址 ws://127.0.0.1:17432
浏览器版本 检测中…

端口固定是为了避免「扩展填的端口与桥起的端口不一致」这种查不出原因的连接失败。 若该端口被占用，桥会明确报端口冲突，请换端口启动桥并重新加载扩展。

接下来，连接本地桥并开始第一次浏览器操作。

快速开始

  1. 启动本地桥。在已安装 BUA 服务端的终端运行：
    bua-server
    保持终端运行，扩展会自动连接 ws://127.0.0.1:17432。
  2. 检查连接。点击 Chrome 工具栏中的 BUA 图标，确认显示已连接；未连接时先检查本地桥是否启动。
  3. 连接你的 Agent。让支持 BUA 的 Agent 或使用 @bua/sdk 的程序连接本地桥，然后选择要操作的标签页。
  4. 开始使用。在浏览器中打开目标网页，再让 Agent 读取内容、截图，或执行点击和输入。

操作时如何查看与停止

  • 页面蓝色边缘泛光表示正在被操作；琥珀色表示降级或异常。
  • 点击 BUA 图标可查看连接状态和操作流水。
  • 关闭 Chrome 顶部的调试横幅会终止本次操作会话。需要停用 BUA 时，在扩展管理页面关闭扩展。
