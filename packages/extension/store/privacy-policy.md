# BUA 隐私政策

**最后更新：2026-10-12**
**适用产品：BUA — Browser Use Agent（Chrome 扩展）**

---

## 一句话总结

**BUA 不收集、不存储、不上传你的任何数据。它没有任何网络代码。**

---

## 1. 我们收集什么

**不收集任何数据。**

BUA 扩展包内**没有任何网络请求代码**。它不联系服务器、不上传遥测、不使用分析服务、
不加载任何远程资源。

## 2. 扩展读取什么，以及为什么

为了让你的本地程序能够操作浏览器，扩展需要读取以下内容 —— **全部只在你的设备上、在内存中处理**：

| 内容 | 何时读取 | 用途 | 是否离开设备 |
|---|---|---|---|
| 当前标签页的 URL 与标题 | 你的程序请求时 | 让程序知道当前在哪一页 | ❌ 否 |
| 页面结构与可见文本（DOM） | 你的程序请求时 | 执行你的程序发出的读取指令 | ❌ 否 |
| 页面截图 | 你的程序请求时 | 执行你的程序发出的截图指令 | ❌ 否 |
| 你打开的标签列表 | 你的程序请求时 | 让你选择要把哪个标签交给程序操作 | ❌ 否 |

**读取范围**：仅限你在扩展引导页明确启用后、由**你自己的本地程序**主动请求的那些标签。
扩展不会在后台扫描你的浏览活动。

## 3. 数据存放在哪里

全部在设备本地，使用 Chrome 的 `chrome.storage.local`：

| 数据 | 内容 | 保留 |
|---|---|---|
| 授权时间戳 | 你确认风险告知的时间 | 直到你卸载扩展 |
| 能力快照 | 当前 CDP 是否可用 | 直到你卸载扩展 |
| 操作流水 | 最近 200 条操作记录（方法名、意图描述、结果） | 超出后自动丢弃；可在弹窗中一键清空 |

**这些数据都不会离开你的设备。**

## 4. 我们与第三方共享什么

**不共享任何数据。** 因为扩展根本不向外发送数据。

## 5. 关于本地连接的一个重要说明

BUA 通过 `127.0.0.1` 上的本地回环连接与本机程序通信。**这个连接不校验调用方身份** ——
任何能访问本机回环地址的程序都可以连接它并操作你的浏览器。

这是刻意的设计取舍：为了让你能自由选择任意工具，而不是被迫绑定某一个特定产品。

**这意味着**：

- 本机上的其他程序（包括恶意软件）也能通过 BUA 操作你的浏览器
- 不过本机恶意软件本来就拥有你的用户权限（可以读取 Chrome 的配置文件与 Cookie），
  BUA 并没有赋予它新的能力上限 —— 但它确实降低了一个门槛

扩展首次启用时会**完整告知这一风险**，并且**需要你主动勾选确认**。

## 6. 关于页面内容可能间接流向 AI 服务

BUA 本身不会上传任何内容。但请注意：

如果你用 BUA 配合一个 **AI agent**（例如某个本地 agent 工具），那么该 agent 可能会把页面内容
发送给它自己的模型服务商。**那是那个 agent 的行为，不是 BUA 的行为**，并且受该 agent 自身的
隐私政策约束。

BUA 的职责边界很清楚：它只把浏览器操作能力提供给本机程序，不参与也不控制本机程序之后如何使用这些能力。

## 7. 我们不做的事

明确声明，以下行为 BUA **一律不做**：

- ❌ 不收集个人身份信息
- ❌ 不收集健康信息
- ❌ 不收集财务与支付信息
- ❌ 不收集认证信息（账号密码、Cookie 值）
- ❌ 不收集个人通信内容
- ❌ 不收集位置信息
- ❌ 不记录浏览历史
- ❌ 不收集用户活动数据用于分析或画像
- ❌ **不向第三方出售或转让任何用户数据**
- ❌ **不将用户数据用于与单一用途无关的目的**
- ❌ **不将用户数据用于判定信用状况或放贷用途**

## 8. Chrome Web Store 用户数据政策合规声明

> The use of information received from Google APIs will adhere to the Chrome Web Store User Data
> Policy, including the Limited Use requirements.

### 关于远程代码申报的说明

本扩展在商店 Privacy 面板中**如实申报了「使用远程代码」**。这里解释清楚它指的是什么，以免与隐私问题混淆：

- **扩展包内没有任何远程代码。** 没有远端 `<script>`、没有 `eval()`、没有 `new Function()`、没有远端 `import`。
- 申报的原因是：扩展使用 `chrome.debugger` API 执行本机程序下发的浏览器操作指令。Chrome 官方在 Manifest V3 要求中把 **Debugger API 与 User Scripts API 列为允许远程执行的两个例外**，并要求使用者必须申报。
- **这与隐私无关**：所有指令都来自本机，扩展不接收任何来自网络的内容，也不向外发送任何内容。

官方依据：[Additional Requirements for Manifest V3](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements)

## 9. 儿童隐私

本扩展不面向 13 岁以下儿童，也不会有意收集儿童的任何信息。

## 10. 政策变更

若本政策有实质变更，我们会更新本文档顶部的日期，并在扩展的更新说明中告知。由于本扩展不收集
任何数据，预期不会出现需要用户重新同意的变更。

## 附：如何自行验证本政策

我们鼓励你不信任任何隐私声明，而是自己验证：

1. 打开 `chrome://extensions`，找到 BUA，点击「详情」
2. 查看权限列表 —— 你会看到它**没有申请任何网站访问权限**（`host_permissions` 为空）
3. 在 `chrome://extensions` 打开开发者模式，使用「检查视图 → service worker」
   打开扩展的后台调试器
4. 切到 Network 标签 —— 你会看到**没有任何网络请求**
5. 阅读源码：`packages/extension/src/background.ts` 中唯一的 socket 是
   `ws://127.0.0.1:17432`
