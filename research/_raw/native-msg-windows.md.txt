<p>Extensions can exchange messages with native applications using an API that is similar to
the other <a href="/docs/extensions/develop/concepts/messaging">message passing APIs</a>. Native applications that support this feature must register a
<em>native messaging host</em> that can communicate with the extension. Chrome starts the host in
a separate process and communicates with it using standard input and standard output streams.</p>

<h2 id="native-messaging-host" data-text="Native messaging host" tabindex="-1">Native messaging host</h2>

<p>To register a native messaging host, the application must save a file that
defines the native messaging host configuration.</p>

<p>An example of the file is as follows:</p>
<div></div><devsite-code><pre class="devsite-click-to-copy" translate="no" dir="ltr" is-upgraded syntax="JSON"><code translate="no" dir="ltr"><span class="devsite-syntax-p">{</span>
<span class="devsite-syntax-w">  </span><span class="devsite-syntax-nt">"name"</span><span class="devsite-syntax-p">:</span><span class="devsite-syntax-w"> </span><span class="devsite-syntax-s2">"com.my_company.my_application"</span><span class="devsite-syntax-p">,</span>
<span class="devsite-syntax-w">  </span><span class="devsite-syntax-nt">"description"</span><span class="devsite-syntax-p">:</span><span class="devsite-syntax-w"> </span><span class="devsite-syntax-s2">"My Application"</span><span class="devsite-syntax-p">,</span>
<span class="devsite-syntax-w">  </span><span class="devsite-syntax-nt">"path"</span><span class="devsite-syntax-p">:</span><span class="devsite-syntax-w"> </span><span class="devsite-syntax-s2">"C:\\Program Files\\My Application\\chrome_native_messaging_host.exe"</span><span class="devsite-syntax-p">,</span>
<span class="devsite-syntax-w">  </span><span class="devsite-syntax-nt">"type"</span><span class="devsite-syntax-p">:</span><span class="devsite-syntax-w"> </span><span class="devsite-syntax-s2">"stdio"</span><span class="devsite-syntax-p">,</span>
<span class="devsite-syntax-w">  </span><span class="devsite-syntax-nt">"allowed_origins"</span><span class="devsite-syntax-p">:</span><span class="devsite-syntax-w"> </span><span class="devsite-syntax-p">[</span><span class="devsite-syntax-s2">"chrome-extension://knldjmfmopnpolahpmmgbagdohdnhkik/"</span><span class="devsite-syntax-p">]</span>
<span class="devsite-syntax-p">}</span>
</code></pre></devsite-code>
<p>The native messaging host manifest file must be valid JSON and contain the following fields:</p>

<dl>
<dt><code translate="no" dir="ltr">name</code></dt>
<dd>Name of the native messaging host. Clients pass this string to <a href="/docs/extensions/reference/api/runtime#method-connectNative"><code translate="no" dir="ltr">runtime.connectNative()</code></a> or <a href="/docs/extensions/reference/api/runtime#method-sendNativeMessage"><code translate="no" dir="ltr">runtime.sendNativeMessage()</code></a>. This name can only contain lowercase alphanumeric characters, underscores and dots. The name can&#39;t start or end with a dot, and a dot can&#39;t be followed by another dot.</dd>
<dt><code translate="no" dir="ltr">description</code></dt>
<dd>Short application description.</dd>
<dt><code translate="no" dir="ltr">path</code></dt>
<dd>Path to the native messaging host binary. On Linux and macOS the path must be absolute. On Windows it can be relative to the directory containing the manifest file. The host process is started with the current directory set to the directory that contains the host binary. For example if this parameter is set to <code translate="no" dir="ltr">C:\Application\nm_host.exe</code> then it will be started with current directory `C:\Application`.</dd>
<dt><code translate="no" dir="ltr">type</code></dt>
<dd>Type of the interface used to communicate with the native messaging host. This parameter has one possible value: <code translate="no" dir="ltr">stdio</code>. It indicates that Chrome should use <code translate="no" dir="ltr">stdin</code> and <code translate="no" dir="ltr">stdout</code> to communicate with the host.</dd>
<dt><code translate="no" dir="ltr">allowed_origins</code></dt>
<dd>List of extensions that should have access to the native messaging host. <code translate="no" dir="ltr">allowed_origins</code> values <em>can&#39;t</em> contain wildcards.</dd>
</dl>

<h3 id="native-messaging-host-location" data-text="Native messaging host location" tabindex="-1">Native messaging host location</h3>

<p>The location of the manifest file depends on the platform.</p>

<p>On <strong>Windows</strong>, the manifest file can be located anywhere in the file system. The application
installer must create a registry key, either
<code translate="no" dir="ltr">HKEY_LOCAL_MACHINE\SOFTWARE\Google\Chrome\NativeMessagingHosts\com.my_company.my_application</code> or
<code translate="no" dir="ltr">HKEY_CURRENT_USER\SOFTWARE\Google\Chrome\NativeMessagingHosts\com.my_company.my_application</code>, and
set the default value of that key to the full path to the manifest file. For example, using the
following command:</p>
<div></div><devsite-code><pre class="devsite-click-to-copy" translate="no" dir="ltr" is-upgraded syntax="Text only"><code translate="no" dir="ltr">REG ADD "HKCU\Software\Google\Chrome\NativeMessagingHosts\com.my_company.my_application" /ve /t REG_SZ /d "C:\path\to\nmh-manifest.json" /f
</code></pre></devsite-code>
<p>or using the following <code translate="no" dir="ltr">.reg</code> file:</p>
<div></div><devsite-code><pre class="devsite-click-to-copy" translate="no" dir="ltr" is-upgraded syntax="Text only"><code translate="no" dir="ltr">Windows Registry Editor Version 5.00
[HKEY_CURRENT_USER\Software\Google\Chrome\NativeMessagingHosts\com.my_company.my_application]
@="C:\\path\\to\\nmh-manifest.json"
</code></pre></devsite-code>
<p>When Chrome looks for native messaging hosts, first the 32-bit registry is queried, then the 64-bit
registry.</p>

<p>On <strong>macOS</strong> and <strong>Linux</strong>, the location of the native messaging host&#39;s manifest file varies by the
browser (Google Chrome, Google Chrome for Testing or Chromium). The system-wide native messaging hosts are looked up at a fixed
location, while the user-level native messaging hosts are looked up in the <code translate="no" dir="ltr">NativeMessagingHosts/</code> subdirectory
of the <a href="https://chromium.googlesource.com/chromium/src/+/HEAD/docs/user_data_dir.md">user profile directory</a>.</p>
<aside class="note"><strong>Note:</strong><span> In versions of Chrome earlier than Chrome 146, Google Chrome for Testing used the same locations as Google Chrome.</span></aside>
<dl>
<dt>macOS (system-wide)</dt>
<dd>Google Chrome: <code translate="no" dir="ltr">/Library/Google/Chrome/NativeMessagingHosts/com.my_company.my_application.json</code></dd>
<dd>Google Chrome for Testing: <code translate="no" dir="ltr">/Library/Google/ChromeForTesting/NativeMessagingHosts/com.my_company.my_application.json</code></dd>
<dd>Chromium: <code translate="no" dir="ltr">/Library/Application Support/Chromium/NativeMessagingHosts/com.my_company.my_application.json</code></dd>
<dt>macOS (user-specific, <em>default</em> path)</dt>
<dd>Google Chrome: <code translate="no" dir="ltr">~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.my_company.my_application.json</code></dd>
<dd>Google Chrome for Testing: <code translate="no" dir="ltr">~/Library/Application Support/Google/ChromeForTesting/NativeMessagingHosts/com.my_company.my_application.json</code></dd>
<dd>Chromium: <code translate="no" dir="ltr">~/Library/Application Support/Chromium/NativeMessagingHosts/com.my_company.my_application.json</code></dd>
<dt>Linux (system-wide)</dt>
<dd>Google Chrome: <code translate="no" dir="ltr">/etc/opt/chrome/native-messaging-hosts/com.my_company.my_application.json</code></dd>
<dd>Google Chrome for Testing: <code translate="no" dir="ltr">/etc/opt/chrome_for_testing/native-messaging-hosts/com.my_company.my_application.json</code></dd>
<dd>Chromium: <code translate="no" dir="ltr">/etc/chromium/native-messaging-hosts/com.my_company.my_application.json</code></dd>
<dt>Linux (user-specific, <em>default</em> path)</dt>
<dd>Google Chrome: <code translate="no" dir="ltr">~/.config/google-chrome/NativeMessagingHosts/com.my_company.my_application.json</code></dd>
<dd>Google Chrome for Testing: <code translate="no" dir="ltr">~/.config/google-chrome-for-testing/NativeMessagingHosts/com.my_company.my_application.json</code></dd>
<dd>Chromium: <code translate="no" dir="ltr">~/.config/chromium/NativeMessagingHosts/com.my_company.my_application.json</code></dd>
</dl>

<h3 id="native-messaging-host-protocol" data-text="Native messaging protocol" tabindex="-1">Native messaging protocol</h3>

<p>Chrome starts each native messaging host in a separate process and communicates with it using
standard input (<code translate="no" dir="ltr">stdin</code>) and standard output (<code translate="no" dir="ltr">stdout</code>). The same format is used to send messages in
both directions; each message is serialized using JSON, UTF-8 encoded and is preceded with 32-bit
message length in native byte order. The maximum size of a single message from the native messaging
host is 1 MB, mainly to protect Chrome from misbehaving native applications. The maximum size of the
message sent to the native messaging host is 64 MiB.</p>

<p>The first argument to the native messaging host is the origin of the caller, usually
<code translate="no" dir="ltr">chrome-extension://[ID of allowed extension]</code>. This allows native messaging hosts to identify the
source of the message when multiple extensions are specified in the <code translate="no" dir="ltr">allowed_origins</code> key in the
<a href="#native-messaging-host">native messaging host manifest</a>.</p>

<p>On Windows, the native messaging host is also passed a command line argument with a handle to the
calling Chrome native window: <code translate="no" dir="ltr">--parent-window=&lt;decimal handle value&gt;</code>. This lets the native
messaging host create native UI windows that are correctly parented. Note that this value will be
0 if the calling context is a service worker.</p>

<p>When a messaging port is created using <a href="/docs/extensions/reference/api/runtime#method-connectNative"><code translate="no" dir="ltr">runtime.connectNative()</code></a> Chrome starts a native messaging
host process and keeps it running until the port is destroyed. On the other hand, when a message is
sent using <a href="/docs/extensions/reference/api/runtime#method-sendNativeMessage"><code translate="no" dir="ltr">runtime.sendNativeMessage()</code></a>, without creating a messaging port, Chrome starts a new
native messaging host process for each message. In that case the first message generated by the host
process is handled as a response to the original request, and Chrome will pass it to the response
callback specified when <a href="/docs/extensions/reference/api/runtime#method-sendNativeMessage"><code translate="no" dir="ltr">runtime.sendNativeMessage()</code></a> is called. All other messages generated by
the native messaging host in that case are ignored.</p>

<h2 id="native-messaging-client" data-text="Connecting to a native application" tabindex="-1">Connecting to a native application</h2>

<p>Sending and receiving messages to and from a native application is very similar to cross-extension
messaging. The main difference is that <a href="/docs/extensions/reference/api/runtime#method-connectNative"><code translate="no" dir="ltr">runtime.connectNative()</code></a> is used instead of
<a href="/docs/extensions/reference/api/runtime#method-connect"><code translate="no" dir="ltr">runtime.connect()</code></a>, and <a href="/docs/extensions/reference/api/runtime#method-sendNativeMessage"><code translate="no" dir="ltr">runtime.sendNativeMessage()</code></a> is used instead of
<a href="/docs/extensions/reference/api/runtime#method-sendMessage"><code translate="no" dir="ltr">runtime.sendMessage()</code></a>.</p>

<p>To use these methods, the &quot;nativeMessaging&quot; permission must be <a href="/docs/extensions/develop/concepts/declare-permissions">declared</a> in your
extension&#39;s manifest file.</p>

<p>These methods are not available inside content scripts, only inside your
extension&#39;s pages and service worker. To communicate from a content script to
the native application, send the message to your service worker to
pass it along to the native application.</p>
<aside class="warning"><strong>Warning:</strong><span> Because content scripts share a renderer process with untrusted web
pages, your service worker must validate <code translate="no" dir="ltr">sender.origin</code> (or <code translate="no" dir="ltr">sender.url</code>) and
sanitize the message payload before forwarding any data to the native host.</span></aside>

message:</p>

<span class="devsite-syntax-p">});</span>
<span class="devsite-syntax-nx">port</span><span class="devsite-syntax-p">.</span><span class="devsite-syntax-nx">onDisconnect</span><span class="devsite-syntax-p">.</span><span class="devsite-syntax-nx">addListener</span><span class="devsite-syntax-p">(()</span><span class="devsite-syntax-w"> </span><span class="devsite-syntax-o">=</span>&gt;<span class="devsite-syntax-w"> </span><span class="devsite-syntax-p">{</span>

<h2 id="native-messaging-debugging" data-text="Debug native messaging" tabindex="-1">Debug native messaging</h2>

<p>When native messaging failures occur, diagnostic output is written to Chrome&#39;s
error log.</p>

<h3 id="debug-windows" data-text="Windows" tabindex="-1">Windows</h3>

<p>Launch Chrome with <a href="https://www.chromium.org/for-testers/enable-logging">logging enabled</a>:</p>
<div></div><devsite-code><pre class="devsite-click-to-copy" translate="no" dir="ltr" is-upgraded syntax="Text only" syntax-guessed><code translate="no" dir="ltr">chrome.exe --enable-logging --log-level=1

<p>Pass <code translate="no" dir="ltr">--user-data-dir=&quot;%TEMP%\nm-debug&quot;</code> to launch a separate instance without

<p>To view the output, stream <code translate="no" dir="ltr">chrome_debug.log</code> using PowerShell:</p>

<code translate="no" dir="ltr">launch_context.cc</code> or <code translate="no" dir="ltr">native_message_process_host.cc</code>.</p>

<h3 id="key-logging-details" data-text="Key logging details" tabindex="-1">Key logging details</h3>

<ul>
<li>Manifest lookup and parse failures in <code translate="no" dir="ltr">launch_context.cc</code> are logged as
warnings. Use <code translate="no" dir="ltr">--log-level=1</code> rather than <code translate="no" dir="ltr">2</code> (ERROR), which suppresses these
startup diagnostics.</li>
<li>Search for <code translate="no" dir="ltr">launch_context</code> to find manifest and binary launch errors, and
<code translate="no" dir="ltr">native_messag</code> to find payload size and pipe communication errors.</li>
</ul>

<h3 id="common-errors" data-text="Common errors" tabindex="-1">Common errors</h3>

<p>Here are some common errors and tips for solving them:</p>

<p><strong>Failed to start native messaging host.</strong></p>

<p>Check whether you have sufficient permissions to execute the native messaging host file.</p>

<p><strong>Invalid native messaging host name specified.</strong></p>

<p>Check whether the name contains invalid characters. Only lowercase alphanumeric characters,
underscores, and dots are allowed. A name cannot start or end with a dot, and a dot cannot be
followed by another dot.</p>

<p><strong>Native host has exited.</strong></p>

<p>The pipe to the native messaging host was broken before the message was read by Chrome. This is most
likely initiated from your native messaging host.</p>

<p><strong>Specified native messaging host not found.</strong></p>

<p>Check the following:</p>

<ul>
<li>Is the name spelled correctly in the extension and in the manifest file?</li>
<li>On Windows, does the registry key exist under <code translate="no" dir="ltr">HKEY_CURRENT_USER</code> or
<code translate="no" dir="ltr">HKEY_LOCAL_MACHINE</code>, and does its default value point to the full manifest
path? Chrome queries the 32-bit registry view first, then the 64-bit view.
Use <code translate="no" dir="ltr">regedit</code> to verify the key. See
<a href="#native-messaging-host-location">native messaging host location</a>.</li>
<li>On macOS and Linux, is the manifest file located in the expected directory
and named after the host (such as <code translate="no" dir="ltr">com.my_company.my_application.json</code>)? See
<a href="#native-messaging-host-location">native messaging host location</a>.</li>
<li>Is the manifest file in the correct format? In particular, is the JSON valid and well-formed and do the
values match the definition of a <a href="#native-messaging-host">native messaging host manifest</a>?</li>
<li>Does the file specified in <code translate="no" dir="ltr">path</code> exist? On Windows, paths may be relative, but on macOS and Linux,
the paths must be absolute.</li>
</ul>

<p><strong>Access to the specified native messaging host is forbidden.</strong></p>

<p>Is the extension&#39;s origin listed in <code translate="no" dir="ltr">allowed_origins</code>?</p>

<p><strong>Error when communicating with the native messaging host.</strong></p>

<p>This indicates an incorrect implementation of the communication protocol in the native messaging host.</p>

<ul>
<li>Make sure that all output in <code translate="no" dir="ltr">stdout</code> adheres to the <a href="#native-messaging-host-protocol">native messaging protocol</a>. If you want
to print some data for debugging purposes, write to <code translate="no" dir="ltr">stderr</code>.</li>
<li>Make sure that the 32-bit message length is in the platform&#39;s native integer format (little-endian
/ big-endian).</li>
<li>The message length must not exceed 1024*1024.</li>
<li>The message size must be equal to the number of bytes in the message. This may differ from the
&quot;length&quot; of a string, because characters may be represented by multiple bytes.</li>
<li><strong>Windows-only:</strong> Make sure that the program&#39;s I/O mode is set to <code translate="no" dir="ltr">O_BINARY</code>. By default, the I/O
mode is <code translate="no" dir="ltr">O_TEXT</code>, which corrupts the message format as line breaks (<code translate="no" dir="ltr">\n</code> = <code translate="no" dir="ltr">0A</code>) are replaced with
Windows-style line endings (<code translate="no" dir="ltr">\r\n</code> = <code translate="no" dir="ltr">0D 0A</code>). The I/O mode can be set using <a href="https://learn.microsoft.com/cpp/c-runtime-library/reference/setmode"><code translate="no" dir="ltr">__setmode</code></a>.</li>
</ul>
