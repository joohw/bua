<h2 id="step-1-prepare-the-extension-to-be-submitted">Step 1: Prepare the extension to be submitted</h2>
<p>To prepare an extension to be submitted via Partner Center, to be published at the Microsoft Edge Add-ons website, do the following steps.</p>
<!-- ---------------------------------- -->
<h4 id="have-a-working-prototype-of-the-extension">Have a working prototype of the extension</h4>
<p>Before publishing your extension, you must have a working prototype of the extension ready.  See <a href="../getting-started/" data-linktype="relative-path">Get started developing an extension</a>.</p>
<!-- ---------------------------------- -->
<h4 id="create-a-developer-account">Create a developer account</h4>
<p>To get started, visit <a href="https://partner.microsoft.com/dashboard/microsoftedge/public/login?ref=dd" data-linktype="external">Partner Center</a>.  This is where every developer (new or existing) must go to publish or manage their extensions.</p>
<p>Use your active developer account to submit the extension at the Microsoft Edge Add-ons website.  If you don't have a developer account, create a new developer account.  To open a new developer account and register for the Microsoft Edge program, see <a href="create-dev-account" data-linktype="relative-path">Register as a Microsoft Edge extension developer</a>.</p>
<!-- ---------------------------------- -->
<h4 id="create-a-zip-file-for-the-extension-package">Create a .zip file for the extension package</h4>
<p>Create a <code>.zip</code> file that's your extension package.  The extension package must include the following files:</p>
<ul>
<li><p>The extension manifest that specifies details such as the name of the extension, short description, permissions, and default language.</p>
</li>
<li><p>Images and other files required by the extension.</p>
</li>
</ul>
<!-- ---------------------------------- -->
<h4 id="review-manifest-field-values">Review manifest field values</h4>
<p>Before uploading your package to Partner Center, inspect the manifest file to make sure that the field values match your preferred display on the <strong>Store Listings</strong> page, as follows.</p>
<p>The following fields in the manifest file are automatically included in your extension's product listing at the Microsoft Edge Add-ons website:</p>
<ul>
<li><p>The <code>Name</code> field, which populates the <strong>Extension name</strong> on the <strong>Details for &lt;language&gt;</strong> page.</p>
</li>
<li><p>The <code>Description</code> field, which populates the <strong>Description</strong> on the <strong>Details for &lt;language&gt;</strong> page.</p>
<p>Fill in the <code>Description</code> field, to explicitly provide a catchy description that will be displayed at the top of the listing for the extension.</p>
<ul>
<li><p>If you include a <code>short description</code> in the extension manifest file, that short description is displayed in your store listing.</p>
</li>
<li><p>If you don't include a <code>short description</code> in the manifest file, the first few lines of the <code>Description</code> are displayed in your store listing.  We recommend providing a <code>short description</code>, to avoid content repetition on your store listing page.</p>
</li>
</ul>
</li>
</ul>
<p>Later, after you upload your package, you'll have an opportunity to modify some fields at Partner Center.  However, the above fields are read-only on the extension's <strong>Store Listings</strong> page at Partner Center, which is described in <a href="#step-7-enter-store-listing-details-for-each-language" data-linktype="self-bookmark">Step 7: Enter store listing details for each language</a>, below.</p>
<p>See also:</p>
<ul>
<li><a href="../getting-started/manifest-format" data-linktype="relative-path">Manifest file format for extensions</a></li>
</ul>

<p>The <strong>Overview</strong> page opens:</p>
<p><img src="publish-extension-images/partner-center-extension-home.png" alt="Overview page" data-linktype="relative-path"></p>

<!-- ------------------------------ -->
<h4 id="visibility">Visibility</h4>
<p>Select one of the following visibility options to define whether your extension is discoverable at the Microsoft Edge Add-ons website:</p>
<ul>
<li><p><code>Public</code> (default) - Allows everyone to discover your extension through:</p>
<ul>
<li>Search.</li>
<li>Browsing at the Microsoft Edge Add-ons website.</li>
<li>Using the listing URL for your extension at the Microsoft Edge Add-ons website.  The listing URL is available on your Partner Center dashboard on the Extension <strong>Overview</strong> page.</li>
</ul>
</li>
<li><p><code>Hidden</code> - Removes an extension from search results or browsing at the Microsoft Edge Add-ons website.  To distribute a hidden extension at the Microsoft Edge Add-ons website, you must share the listing URL of the extension with your customers.</p>
</li>
</ul>
<p>You can change the visibility of your extension from <strong>Public</strong> to <strong>Hidden</strong>.  Users who installed your extension while the visibility was set to <strong>Public</strong> retain access to your extension and receive any updates you make available at the Microsoft Edge Add-ons website.</p>
<!-- ------------------------------ -->
<h4 id="markets">Markets</h4>
<p>Define the specific markets in which you plan to offer your extension.  The default setting for markets is all markets and that includes any future markets that are added later.</p>
<ol>
<li><p>To choose specific markets, click the <strong>Change markets</strong> button.</p>
</li>
<li><p>Select or clear the checkbox for each market.</p>
<p>Or, select <strong>Unselect all</strong>, and then select individual markets.</p>
<p>You can change the markets where your extension is offered.  A user who installs your extension while it's available in the user's market retains access to your extension.  However, the user doesn't have access to any future updates that are submitted at the Microsoft Edge Add-ons website.</p>
<p>You have now filled in the <strong>Availability</strong> page for the extension at Partner Center.</p>
</li>
<li><p>Click <img src="publish-extension-images/save-icon.png" alt="Save &amp; Continue icon" data-linktype="relative-path"> <strong>Save &amp; Continue</strong> in the upper right.</p>
<p>The <strong>Properties</strong> page opens.</p>
</li>
</ol>

<h2 id="if-a-single-locale-appears-but-the-package-includes-multiple-languages">If a single locale appears, but the package includes multiple languages</h2>
<p>Sometimes only one locale appears in the <strong>Store Listings</strong> tab at Partner Center, even though an extension's package includes multiple languages.  This happens when the manifest file uses hardcoded strings instead of localized message references.</p>
<p>To ensure that all supported locales are detected:</p>
<ul>
<li><p>Update your <code>manifest.json</code> file by replacing the <code>name</code> and <code>description</code> fields with i18n placeholders:</p>
<pre><code>{
    "manifest_version": 3,
    "name": "__MSG_extensionName__",
    "description": "__MSG_extensionDescription__"
}
</code></pre>
</li>
<li><p>Include a <code>default_locale</code> in your manifest, such as <code>"default_locale": "en"</code>.</p>
</li>
<li><p>Make sure your <code>_locales</code> folder contains a properly structured <code>messages.json</code> file for each language.  Partner Center uses these message references to identify available languages.  If these message references are missing, the language will be skipped.</p>
<p>The message references are the i18n <code>"name"</code> and <code>"description"</code> keys in each <code>/_locales/messages.json</code> file.  These message references (i18n keys) correspond to the <code>"__MSG_extensionName__"</code> and <code>"__MSG_extensionDescription__"</code> placeholders that are used in the <code>"name"</code> and <code>"description"</code> fields of the <code>manifest.json</code> file.  Partner Center uses these message references to determine which languages are available.</p>
</li>
</ul>
<p>See also:</p>
<ul>
<li><a href="https://developer.chrome.com/docs/extensions/reference/api/i18n" data-linktype="external">chrome.i18n</a> - API to implement internationalization throughout an app or extension.</li>
<li><a href="../getting-started/manifest-format" data-linktype="relative-path">Manifest file format for extensions</a>
<ul>
<li><a href="https://developer.chrome.com/docs/extensions/reference/manifest" data-linktype="external">Manifest file format</a> in Chrome docs.</li>
</ul>
</li>
</ul>

<h2 id="if-the-extension-is-flagged-as-potentially-malware">If the extension is flagged as potentially malware</h2>
<p>If the extension is flagged as malware or a potentially unwanted application (PUA), review <a href="/en-us/legal/microsoft-edge/extensions/developer-policies#122-unwanted-and-malicious-software" data-linktype="absolute-path">1.2.2 Unwanted and malicious software</a> in <em>Developer policies for the Microsoft Edge Add-ons website</em>.</p>
<p>Make sure that your extension's code and functionality complies with all requirements and guidelines.  For security reasons, Microsoft doesn't disclose exact triggers.</p>
<!-- ========================================================================== -->
<h2 id="responsible-ai-for-the-ai-generated-description-of-an-extension">Responsible AI for the AI-generated description of an extension</h2>
<p>The description of your extension at the Microsoft Edge Add-ons website can optionally be generated by using AI.  You can compose the description manually, or you can use AI to help generate the description.  This AI-generated description feature uses responsible AI, as described below.</p>
<!-- ---------------------------------- -->
<h4 id="process-of-using-the-ai-generated-description-feature">Process of using the AI-generated description feature</h4>
<p>To use AI to help generate a description of the extension for a particular language, you provide prompt input text, generate a description, and then edit the resulting AI-generated description.  The steps are detailed in <a href="#generate-the-description-with-ai" data-linktype="self-bookmark">Generate the description with AI</a>, above.</p>
<p>As a Microsoft Edge extension developer, you use Microsoft Partner Center to make your extension available to users at the Microsoft Edge Add-ons website.  To submit an extension, you provide data for the extension's listing page, including the extension name, description, and screenshots.</p>
<p>A high-quality description for the extension is important, for the users to understand the features and functionality of the extension, and to make an informed decision whether to install the extension.</p>
<ul>
<li><p>The AI-generated description is a feature powered by Azure OpenAI, which recommends a description, for you to inspect and edit as needed.  This AI feature uses the extension package (including the manifest, code files, and image files), uploaded screenshots, and optional prompt text to generate a high-quality and policy-compliant description.</p>
</li>
<li><p>You can apply, edit, or discard the generated text before submitting the extension.  It is strongly recommended that you verify the AI-generated description, editing it as needed, before publishing the description for users.</p>
</li>
<li><p>The description can be generated for multiple languages (one at a time, individually).</p>
</li>
</ul>
<p>This process ensures transparency, and compliance with <a href="https://www.microsoft.com/ai/principles-and-approach" data-linktype="external">Microsoft Responsible AI Principles and Approach</a>, while helping you craft an accurate and user-friendly description.  However, AI-generated content might be inaccurate sometimes, and it's strongly recommended that you verify the description, and edit it as needed, before publishing the extension.</p>
<!-- ---------------------------------- -->
<h4 id="inputs-used-for-the-ai-generated-description">Inputs used for the AI-generated description</h4>
<p>The AI-generated description is based on the following inputs for the AI model:</p>
<ul>
<li><p>The uploaded extension package, including the manifest, code files, and image files.  These image files are part of the extension.</p>
</li>
<li><p>Any screenshots of the running extension that you've uploaded via the <strong>Details for &lt;language&gt;</strong> page.  These screenshots are displayed at the Microsoft Edge Add-ons website.</p>
</li>
<li><p>Any input prompt text that you enter.</p>
</li>
<li><p>The language, such as English.</p>
</li>
</ul>
<!-- ---------------------------------- -->
<h4 id="how-the-ai-generated-description-feature-was-evaluated">How the AI-generated description feature was evaluated</h4>
<p>The AI-generated description feature has undergone substantial testing, to identify failure modes and scenarios that might cause AI-generated keywords to do or say things outside of the feature's intended uses or that don't support the principles at <a href="https://www.microsoft.com/ai/responsible-ai" data-linktype="external">Responsible AI at Microsoft: Ethical policies and practices</a>.</p>
<!-- ---------------------------------- -->
<h4 id="safeguards-for-the-ai-generated-description">Safeguards for the AI-generated description</h4>
<p>The following safeguards are in place for the AI-generated description:</p>
<ul>
<li><p>The AI-generated description is based exclusively on the extension package, uploaded screenshots, and any prompt text that you provide.  See <a href="#inputs-used-for-the-ai-generated-description" data-linktype="self-bookmark">Inputs used for the AI-generated description</a>, above.</p>
</li>
<li><p>Providing input prompt text is optional.</p>
</li>
<li><p>The inputs are sent to the AI model, which then generates a description.</p>
</li>
<li><p>You have full control over the AI-generated description, and can choose to use it as-is, edit it, or discard it.</p>
</li>
</ul>
